# Keyboard Pro — project notes for Claude Code

Custom iPhone keyboard (iOS keyboard extension + host app). Goal: an iPhone keyboard that feels like the
Android keyboard — long-press any letter to type a symbol — plus "Tac Tile" switch sounds and haptics.

## About the developer
- Works on a **Windows 11 laptop**, no Mac. New to Mac and Xcode.
- Never assume Xcode, `xcodebuild` or a simulator runs locally. All builds run in **GitHub Actions**.
- Explain Apple- or Xcode-specific steps plainly.

## Repo and build
- Local folder: `D:\dev\Keyboard Pro`. GitHub repo: `Jopheus/Keyboard-Pro`.
- The Xcode project is generated by **XcodeGen** from `project.yml`. No `.xcodeproj` is committed.
  Info.plists are generated into `Supporting/` at build time.
- `build.yml` is the GitHub Actions workflow (macos-15 runner, newest Xcode 26 for Liquid Glass).
  It runs `xcodegen generate`, builds an unsigned archive and uploads `KeyboardPro.ipa` as an artifact.
  In the GitHub repo it must live at `.github/workflows/build.yml`.
- Push to GitHub, then check the Actions run for build errors. That build is the only compile check.
- Targets: `KeyboardPro` (SwiftUI host app, `App/`) and `Keyboard` (app extension, `Keyboard/`).
  Deployment target iOS 15. Must run on iPhone 12 and newer. `RequestsOpenAccess: true` (needed for haptics).

## Code map
- `Keyboard/KeyboardViewController.swift`: main keyboard UI and input logic (large file)
- `Keyboard/Settings.swift`: settings model/storage. `Keyboard/SettingsPanel.swift`: in-keyboard settings UI
- `Keyboard/Feedback.swift`: sound and haptic engine ("Tac Tile")
- `Keyboard/Suggestions.swift`: autocomplete/suggestions. `Keyboard/EmojiData.swift`, `EmojiNames.swift`: emoji
- `Keyboard/Sounds/<Profile>/<Profile>_press_{generic_0-4,space,enter,backspace}.caf`: switch sounds
- `App/KeyboardProApp.swift`: host app home screen (setup steps, settings menu, test field)
- `App/SettingsViews.swift`: the keyboard's settings as SwiftUI screens in the app. The app target
  also compiles `Keyboard/Settings.swift`, `Keyboard/Feedback.swift` and bundles `Keyboard/Sounds`.
- Settings are shared through the App Group `group.com.example.keyboardpro` (entitlements in
  `project.yml`; the workflow ad-hoc signs with them). The app bumps `KBSettings.revision` on each
  change; the keyboard reloads theme/sound/height in `viewWillAppear` when it sees a new revision.
- `Design/`: app icon SVGs and `make_icon.py`. `ThirdParty/kbsim-LICENSE.md`: sound licence
- `.backup-*`: old snapshots. Ignore them and don't edit them.

## Naming and tiers
- The app is "Keyboard Pro". Use `KeyboardPro` in code. The old `AndroidKeyboard` naming is retired.
- **Pro** = normal/free users. **Max** = advanced/paid users.
- Pro (basic) settings: long-press duration, custom dictionary words, auto-complete and auto-correct,
  haptic level for typing and for long press, light/dark theme.
- Max features: remap symbols, smart suggestions from typing history, adjustable keyboard height.

## Layout decisions
- Separate number row on top. Symbols are remapped because numbers have their own row.
- The comma and full-stop keys are removed. An emoji key is on the bottom row.
- Long-press any letter to type its symbol.

## Tac Tile sound engine
- Switch sound profiles plus haptics. Profiles: Blue = Clicky, Brown = Typewriter, Red = Cream,
  Tofu = Tofu ("Almost soundless, light vibration"), plus Custom.
- Sounds come from kbsim (github.com/tplai/kbsim, MIT): Cream, Panda, Alpaca, Tea, Black Ink, Red Ink,
  Clacky, Typewriter, Clicky, Spring, Hollow, Tofu.
- **Before shipping:** re-check kbsim issue #44 (sound origin/licence).

## Product direction
- All keyboard settings should live in the Keyboard Pro app. The keyboard's gear icon should open the app.
  Done: the app shows every setting, and the gear opens the app via `keyboardpro://settings`
  (`openHostApp()` in `KeyboardViewController.swift`, responder-chain trick). The in-keyboard
  `SettingsPanel` is now only a fallback if opening the app fails; keep it in sync or retire it later.
